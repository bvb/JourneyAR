# Journey AR

Браузерное AR-приложение для артбука Journey: при наведении камеры на страницу (Natural Feature Tracking) показывает анимированную 3D-сцену и играет звук. Работает в браузере на Android, iPhone и PC. Ремейк Unity + Vuforia приложения DAQRI 2012 года.

**План и принятые решения — [.plans/plan.md](.plans/plan.md)** (источник истины; там же соответствие страниц, сцен и звуков).

## Структура

- `journey-ar/` — основное приложение (Vite + TS + three.js). `assets/` — publicDir Vite: `models/*.glb`, `audio/*.mp3`, `nft/<scene>/`, `scenes.json`, иконки (`favicon.ico`, PNG, `site.webmanifest`, `logo.svg`).
- `journey-virtual-book-camera/` — виртуальная камера для тестов (страницы в 3D, выдача потока в приложение).
- `tools/` — конвейер ассетов (Unity-экспорт, NFT, gltf-transform, ffmpeg). Пути к внешним программам — в `tools/config.mjs`, переопределяются переменными окружения.
- `book-ar-pages/` — изображения отслеживаемых страниц (в git, через LFS).
- `assets-favicon/` — иконки приложения от пользователя (favicon для браузеров) — источник для `ui:publish`; файлы как даны (не форматируются prettier).
- Вне git: `book/`, `unity-data-project/`, `android-ar-viewer.1.0/`, `videos-from-internet/` (видео работы оригинального приложения — эталон вида сцен).

## Команды (из корня)

- `npm run dev` — приложение на https://localhost:5173 (самоподписанный сертификат, доступно в LAN).
- `npm run dev:vcam` — виртуальная камера на https://localhost:5174 (блоки «Запись» и «WebRTC»): страницы клавишами 1–6 (0 — без страницы), поза камеры полями, пресетами и мышью; API `window.__vcam` (`setPage`, `setPose`, `setFrame`, `getGroundTruth`, `project`, `setPaused`/`renderFrame`).
- `npm run check` — typecheck + lint + prettier + unit-тесты.
- `npm run e2e` — быстрый набор Playwright (~40 с): Edge, по одному короткому тесту на функцию (тесты с тегом `@regression` пропускаются).
- `npm run e2e:full` — регрессия (~5 мин): все тесты journey-ar и виртуальной камеры в Edge и изолированном Chromium — метрики трекинга, все страницы, кривые звука, жесты, повторные циклы. Тяжёлые и подробные тесты помечаются `{ tag: '@regression' }`.
- `npm run build` — сборка всех workspaces.
- `npm run check-env` — проверка Unity, Blender, ffmpeg и исходных папок.
- `npm run unity:fix` — применить правки к `unity-data-project` (идемпотентно, резервные копии в `tools/.out/unity-backup/`); в том числе порядок каналов текстур ARGB4444 (`SHIFTED_TEXTURES`: рип читал их со сдвигом каналов — пляж daqri, солнце Landscape).
- `npm run unity:check` — batchmode-проверка Unity-проекта: компиляция, шейдеры, материалы (отчёт в `tools/.out/unity/`).
- `npm run unity:render` — эталонные рендеры каждого таргета в `tools/.out/reference/`.
- `npm run unity:export` — экспорт каждого таргета в GLB (`tools/.out/export/`) с отчётом `export-report.json`.
- `npm run gltf:inspect` — gltf-validator + сверка GLB с отчётом Unity.
- `npm run scenes:compare` — рендер каждой сцены в three.js (Edge) рядом с эталоном Unity: выгрузка Unity → `tools/.out/compare/<id>.png` и опубликованная оптимизированная модель → `<id>-published.png` (пороги одни). Вручную: `https://localhost:5173/scene-preview.html?scene=<id>&t=<сек>` (только dev-сервер).
- `npm run assets:publish` — GLB (оптимизированные, `tools/assets/optimize.mjs`) и MP3 в `journey-ar/assets`, генерация `scenes.json`; привязка сцен к страницам — поиском текстур таргетов Vuforia на сканах (превью в `tools/.out/anchors/`). Уже записанные привязки сохраняются, пересчёт: `npm run assets:publish -- --reset-anchors`. Там же точка масштабирования (`pinch.pivot` — центр узлов из `pinchPivot` в `tools/scenes.mjs`).
- `npm run ui:publish` — ассеты интерфейса в `journey-ar/assets`: иконки из `assets-favicon/` (манифест — с именем и цветами приложения), `background.jpg` (картинка до включения камеры, из `book/journey-art1600.jpg`) и `logo.svg` — фигурка путника, векторизованная из `mstile-150x150.png` (`tools/images/trace.mjs`: сглаживание, изолиния, упрощение) — для кнопки.
- `npm run pages:normalize` — сканы страниц → `book-ar-pages/normalized/<id>.jpg` (1700×1268, 142.5 dpi, симметричная обрезка).
- `npm run nft:generate -- [id...]` — NFT-маркеры (`.iset/.fset/.fset3`) в `journey-ar/assets/nft/<id>/` (`--pages=`, `--out=` для экспериментов); логи в `tools/.out/logs/`.
- `npm run nft:probe -- [id...] [--together] [--markers=<папка>]` — проверка маркеров без браузера: синтетические кадры с известной позой → Node-сборка jsartoolkit-nft → ошибка позы, время детекта, путаница страниц (`--together` — все маркеры в одном трекере, как в приложении). По умолчанию — маркеры приложения; относительная `--markers` считается от `tools/`.
- После смены страниц: `pages:normalize` → `nft:generate` → `assets:publish` → `nft:probe -- --together`.
- Конвейер целиком: `unity:fix` → `unity:check` → `unity:render` → `unity:export` → `gltf:inspect` → `scenes:compare` → `assets:publish` (Unity закрыт).

## Правила

- Перед коммитом: `npm run check` и `npm run e2e` зелёные; `npm run e2e:full` — только в финале (перед отчётом о завершённой работе), он долгий.
- Ассеты в `journey-ar/assets` не правятся вручную — только скриптами из `tools/` (`assets:publish`, `ui:publish`); в `scenes.json` вручную/через debug-режим подстраиваются только `anchor`. Схема `scenes.json` — `journey-ar/src/scenes/manifest.ts`.
- Система страницы — мм, начало в центре страницы, X вправо, Y к верху страницы, Z из страницы. Поза трекера (`origin: 'center'`) и точная поза vcam — матрица страница → камера в осях OpenGL, мм. Сцены в GLB — в системе таргета (ширина таргета = 1); перевод — `anchorMatrix()`.
- Сцен шесть, page166 (daqri) — последняя. У daqri нет `PinchScale` (щипок задан в `tools/scenes.mjs` → `pinch`), звук — WAV из двух источников (`assets:publish` кодирует в MP3 и складывает громкости), прокрутка неба `SkyScroll` (legacy Animation) публикуется компонентом `AnimatedUVs_Scroll` (`uvScrolls` в `tools/scenes.mjs`); ссылка `TouchRay` на daqri.com и частицы не перенесены, надпись «Tap here» убрана (`removeNodes` в `tools/scenes.mjs`: `assets:publish` удаляет узел).
- Оптимизация GLB (`tools/assets/optimize.mjs`, при `assets:publish`) сохраняет структуру документа: узлы, их трансформации и текстуры не трогаются (приложение ищет узлы по именам, материалы берут текстуры по номеру из `extras`). Позиции не квантуются (иначе меши переезжают в новые дочерние узлы); нормали/касательные — 12 бит, UV в [0, 1] — 14, цвета вершин — 16 (линейные, в 8 битах тёмные полосят); всё сжато `EXT_meshopt_compression` без потерь; PNG → WebP (градиенты `*Ramp*` без потерь), JPEG как есть. gltf-transform пишет glTF-текстуры только для стандартных слотов — номера в `extras` после записи восстанавливаются по изображениям выгрузки (`restoreTextureRefs`); unit-тест в `manifest.test.ts`. Загрузчик — `GLTFLoader` с `MeshoptDecoder` (`src/scenes/load-scene.ts`). Изменения проверять `scenes:compare` (опубликованная модель должна давать ту же разницу с Unity, что и выгрузка).
- `unity-data-project` (Unity 6.6, 6000.6.8f1) вне git: все правки в нём вносятся только через `tools/unity/apply-fixes.mjs` (удаления, оверлей `tools/unity/overlay/` поверх существующих файлов, новые файлы `tools/unity/additions/` с фиксированными GUID, возврат потерянных шейдеров материалам, манифест), чтобы их можно было повторить на чистой копии оригинала. Проект извлечён из пересборки 2017 года; оригинальная сборка 2012 года — `android-ar-viewer.1.0/assets/bin/Data` (Unity 3.5.5f3), её можно читать UnityPy (`python -m venv tools/.out/pyenv`, `pip install UnityPy`), когда нужно выяснить, каким был объект в оригинале. Код экспортёра живёт в `tools/unity-export` (локальный UPM-пакет, `.meta`-файлы коммитятся).
- Fixed-function шейдеры оригинала работают в Unity 6 — не переписывать их: эмуляция Unity — эталон оригинального вида.
- AR-контент рендерится в gamma-режиме Unity: перед первым кадром `configureLegacyRendering(renderer, camera)`, текстуры сцен — `NoColorSpace`, цвета из Unity — как есть (`new Color(r, g, b)`), без `SRGBColorSpace`.
- Видео камеры рисуется внутри WebGL (`src/render/video-background.ts`, обрезка cover по центру, как проекция трекера) на непрозрачном контексте, который создаётся в `main.ts`; `<video>` только декодирует. Не возвращать прозрачный холст поверх видео: аддитивное смешивание тогда закрывает видео (свет Creature становится тёмным).
- Материалы сцен строятся только в `src/scenes/unity-materials.ts` по `extras.unityShader`. Любое изменение материалов, экспортёра или рендера проверять `npm run scenes:compare` (пороги: средняя разница < 4/255, < 1 % пикселей > 32).
- Эталоны Unity рендерятся без HDR намеренно (как 8-битный буфер телефона).
- Отладка в `scene-preview.html`: `?t=` (время), `?hide=<материалы>`, `?ref=<папка эталонов в tools/.out>`; в Unity — `-journeyTargets`, `-journeyHide`, `-journeyTime`, `-journeyOut` (относительно корня репозитория), `-journeyFocus=<объект>` (крупный план объекта) — аргументы `node tools/unity/run-unity.mjs`. Пример крупного плана: `node tools/unity/run-unity.mjs Journey.UnityExport.ReferenceRenderer.RenderAll -journeyTargets creature -journeyFocus polySurface374 -journeyTime 3 -journeyOut tools/.out/reference-creature-head`, затем `scene-preview.html?scene=creature&t=3&ref=reference-creature-head`.
- Unity batchmode не запускается, пока проект открыт в редакторе: попросить пользователя закрыть Unity.
- Трекинг: `src/tracking/` — jsartoolkit-nft в воркере (файлы воркера раздаются по `/nft-worker/` плагином в `vite.config.ts`), кадр 640 px по длинной стороне, одна активная страница, потеря на первом кадре без страницы, фильтр `native`. Портретное видео подаётся трекеру повёрнутым в альбомный кадр (`rotated` в геометрии), поэтому поворот телефона не пересоздаёт трекер. Показываемая поза сглаживается (`src/tracking/pose-smoother.ts`: One Euro + плавное догоняние на каждом кадре экрана). Диагностику ядра ARToolKit (версия, параметры камеры при каждом создании трекера, безвредная ошибка «Error detaching pattern» при остановке) глушит прелюдия, которую `vite.config.ts` ставит перед кодом воркера; остановка трекера ошибок не даёт (отклонённые запросы после `dispose` гасятся). Нагрузка: пока страницы нет в кадре, трекер ищет её раз в 200 мс (первую секунду после потери или старта — на каждом кадре; `src/tracking/search-pacer.ts`); кадр трекеру готовится на GPU из текстуры видео фона с асинхронным чтением (`src/render/gpu-frame-grabber.ts`; `?grab=canvas` — прежний путь через 2D-холст, `src/tracking/frame-grabber.ts`; он же выбирается сам при программном WebGL — SwiftShader в Chromium из Playwright, где асинхронное чтение медленное: в e2e путь через GPU проверяет Edge); холст рисуется только при новом кадре видео (частота камеры), не чаще 60 раз в секунду, до старта не рисуется. Параметры отладки: `?fov=<угол по длинной стороне>` (по умолчанию 63°), `?filter=native|none|oneeuro` (фильтр ядра трекера), `?smooth=off` или `?smooth=<minCutoff>,<beta>,<rotationBeta>,<easing>`, `?debug` (контур страницы и оси).
- Сцены: `src/scenes/ar-scenes.ts` — якорь (поза трекера) → `anchorMatrix(scene.anchor)` → GLB; ленивая загрузка, предзагрузка в фоне после старта трекера, перезапуск анимаций при каждом обнаружении (если страница вернулась в течение 3 с — продолжение с места остановки, `src/scenes/resume-window.ts`; так же и звук), скрытие в кадр потери. Жесты (`src/interaction/scene-gestures.ts`): щипок масштабирует узел `scenes.json` → `pinch.node` в пределах `pinch` относительно его начала или `pinch.pivot` (при уменьшении — точки страницы под ним, чтобы сцена стояла на странице; `src/scenes/pinch-pivot.ts`; Landscape — до 3× от центра моделей в сфере), перетаскивание (один палец, середина двух, мышь) сдвигает сцену в плоскости страницы (`page-point.ts`: точка страницы под пальцем следует за ним), двойное касание — сброс. Размер и сдвиг у каждой сцены сохраняются между обнаружениями (`scene-placement.ts`).
- Звук: `src/audio/scene-audio.ts` — Web Audio, AudioContext открывается кнопкой «Старт» (синхронно в клике); трек с начала при обнаружении (если страница вернулась в течение 3 с — с места остановки, `ResumeWindow`), затухание при потере, бесшовная петля (`loopBounds`), объёмный: `PannerNode` над центром сцены, позиция по сглаженной позе, модель затухания `SPATIAL` в `src/audio/loop-bounds.ts`. Состояние — `window.__journey.audio` (геттер с уровнями до/после панорамы).
- Интерфейс — только кнопка Старт/Стоп внизу по центру (`index.html`, `src/style.css`, `src/ui/start-button.ts`, решение пользователя — других элементов нет): чёрный круг с белым ободком и `logo.svg`; после «Старт» картинка инвертируется (белый круг, чёрная фигурка), ободок толще; пока грузятся NFT-маркеры, модели и звук, по тусклому ободку бежит огонёк (`src/ui/pending-loads.ts`, `window.__journey.loading`); после ошибки ободок красный до следующего «Старт». Запущенная и загруженная кнопка через 0.8 с сворачивается в полупрозрачную полоску (`collapsed`, имя «Показать кнопку»); нажатие или свайп вверх разворачивают её, без нажатия через 3 с она сворачивается снова (константы в `start-button.ts`; в тестах «Стоп» — через `pressStop` из `tests/e2e/helpers.ts`). Текста на экране нет: ошибки — только в консоли (`reportError` в `main.ts`). Пока камера не показывает картинку, холст скрыт и виден фон `background.jpg` (по центру, по высоте окна; класс `camera-on` у `body`). Имя кнопки для тестов — `aria-label` «Старт»/«Стоп».
- Выбор страницы: `src/tracking/page-selector.ts` — одна активная страница; при высокой ошибке трекинга (> 1.2) трекер временно ищет другие страницы, чтобы не держать неверную. Состояние — `window.__journey.scenes`. Состояние трекера — `window.__journey.tracking` (страница, поза, события found/lost); метрики по точной позе — `tests/e2e/tracking.spec.ts`.
- Тестовые источники кадров (`?source=canvas|webrtc|video`) работают только в dev/test-сборке (`import.meta.env.DEV`), запускаются кнопкой «Старт»:
  - `canvas` — виртуальная камера внутри приложения, управление через `window.__vcam`;
  - `webrtc` — поток из открытой vcam (`npm run dev:vcam`) через ретранслятор `/__signal` dev-сервера приложения (работает и на телефоне в LAN); `?room=<имя>` у обоих разводит несколько пар (тесты);
  - `video&src=/__recordings/<имя>.webm` — запись из `journey-ar/tests/recordings` (записи делает vcam: кнопка «Запись» или `__vcam.startRecording()`/`stopRecording(имя)`, рядом `<имя>.json` с точной позой каждого кадра).
- TypeScript закреплён на 6.0.x: typescript-eslint пока поддерживает только `<6.1`.
- three.js закреплён на точной версии (0.187.0) вместе с `@types/three`.
- `mind-ar` не устанавливать через npm: он тянет нативный `canvas` 2.x, который не собирается под Node 26. `.mind` компилировать в браузере (фаза 2).
- npm 11 блокирует install-скрипты; разрешённые перечислены в `allowScripts` корневого `package.json`.

## Тестирование на телефоне (Android)

ПК и телефон в одной сети: открыть `https://<IP-ПК>:5173`, один раз принять предупреждение о сертификате. Брандмауэр Windows должен разрешать входящие подключения для Node.js.
