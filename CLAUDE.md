# Journey AR

Браузерное AR-приложение для артбука Journey: при наведении камеры на страницу (Natural Feature Tracking) показывает анимированную 3D-сцену и играет звук. Работает в браузере на Android, iPhone и PC. Ремейк Unity + Vuforia приложения DAQRI 2012 года.

**План и принятые решения — [.plans/plan.md](.plans/plan.md)** (источник истины; там же соответствие страниц, сцен и звуков). Для людей — [README.md](README.md) (на английском): требования, релизная сборка, запуск, все команды `npm run` — обновлять вместе с командами.

## Структура

- `journey-ar/` — основное приложение (Vite + TS + three.js). `assets/` — publicDir Vite: `models/*.glb`, `audio/*.mp3`, `nft/<scene>/`, `scenes.json`, иконки (`favicon.ico`, PNG, `site.webmanifest`, `logo.svg`).
- `journey-virtual-book-camera/` — виртуальная камера для тестов (страницы в 3D, выдача потока в приложение).
- `tools/` — конвейер ассетов (конвертер APK, NFT, gltf-transform, ffmpeg). Пути к внешним программам и исходникам — в `tools/config.mjs`, переопределяются переменными окружения. `tools/unity-reference/` — замороженные эталонные рендеры Unity 6 (сделаны, пока сцены шли через Unity; перерендерить их больше нечем).
- `original-sources/` — все исходники, из которых получаются данные и ассеты (в git, бинарные — через LFS; не форматируются prettier):
  - `Journey-AR-Viewer.1.0.apk` — оригинальное приложение 2012 года (Unity 3.5.5f3 + Vuforia): сцены, модели, текстуры, звук, датасет Vuforia;
  - `book-ar-pages/Artbook_Journey-page<N>.jpg` — сканы отслеживаемых страниц;
  - `favicon/` — иконки приложения от пользователя (favicon для браузеров), файлы как даны — источник для `ui:publish`;
  - `journey-art1600.jpg` — картинка до включения камеры (источник для `ui:publish`);
  - `creature.mp4`, `journey.mp4` — видео сцен Creature и Character на книге (записи с телефона, как даны); в конвейере не участвуют. В начале README — те же видео как вложения GitHub (плеер) и ссылки на файлы. Плеер прямо в README на GitHub возможен только для видео, загруженных во вложения GitHub (`https://github.com/user-attachments/assets/<id>` отдельной строкой; загрузка — перетаскиванием файла в веб-редактор GitHub, до 10 МБ на бесплатном плане): `media-src` в CSP github.com не пускает `raw`/`media.githubusercontent.com`, так что файлы из репозитория (LFS) в README не воспроизводятся.
- `pages-for-nft/<id>.jpg` — нормализованные страницы (`pages:normalize`): из них NFT-маркеры и страницы виртуальной камеры.
- `.github/workflows/pages.yml` — публикация на GitHub Pages.
- `LICENSE` (MIT, код) и `NOTICE.md` (контент Journey — правообладателям, используется с разрешения; список папок с ним).
- Вне git: `videos-from-internet/` (видео работы оригинального приложения — эталон вида сцен).

## Команды (из корня)

- `npm run dev` — приложение на https://localhost:5173 (самоподписанный сертификат, доступно в LAN).
- `npm run dev:vcam` — виртуальная камера на https://localhost:5174 (блоки «Запись» и «WebRTC»): страницы клавишами 1–6 (0 — без страницы), поза камеры полями, пресетами и мышью; угол обзора — по длинной стороне кадра (как `?fov=` приложения, по умолчанию 63°), смена разрешения его не меняет (как у телефона: 16:9 — обрезка сенсора 4:3); API `window.__vcam` (`setPage`, `setPose`, `setFrame`, `getGroundTruth`, `project`, `setPaused`/`renderFrame`).
- `npm run check` — typecheck + lint + prettier + unit-тесты.
- `npm run e2e` — быстрый набор Playwright (~40 с): Edge, по одному короткому тесту на функцию (тесты с тегом `@regression` пропускаются).
- `npm run e2e:full` — регрессия (~5 мин): все тесты journey-ar и виртуальной камеры в Edge и изолированном Chromium — метрики трекинга, все страницы, кривые звука, жесты, повторные циклы. Тяжёлые и подробные тесты помечаются `{ tag: '@regression' }`.
- `npm run build` — сборка всех workspaces.
- `npm run build-all` — релиз на чистом клоне одной командой: `npm ci` → `apk:setup` → `check-env` → `apk:convert` → `gltf:inspect` → `pages:normalize` → `nft:generate` → `assets:publish` → `ui:publish` → `check` → `build`; приложение — в `journey-ar/dist`. Пересобирает ассеты из `original-sources/` байт в байт (после него `git status` чистый). `npm ci` скачивает ffmpeg 6.1.1 с github.com (`ffmpeg-static`); если GitHub недоступен — `HTTPS_PROXY` или зеркало в `FFMPEG_BINARIES_URL` (`<url>/b6.1.1/ffmpeg-win32-x64.gz`, `win32-x64.README`, `win32-x64.LICENSE`).
- `npm run preview` — релизная сборка на https://localhost:4173.
- `npm run check-env` — проверка ffmpeg, Python с UnityPy, APK (датасет Vuforia читается) и исходников в `original-sources/`.
- `npm run apk:setup` — Python-окружение конвертера (`tools/.out/pyenv`, UnityPy из `tools/apk/requirements.txt`); Python — `py -3` или `PYTHON_FOR_VENV`.
- `npm run apk:convert` — сцены из APK в GLB (`tools/.out/export/<id>.glb`) с отчётом `export-report.json`: `tools/apk/read-apk.py` (UnityPy) выгружает данные сцен в `tools/.out/apk/`, `tools/apk/convert.mjs` собирает GLB (`-- --skip-read` — без повторного чтения APK).
- `npm run gltf:inspect` — gltf-validator + сверка GLB с отчётом.
- `npm run gltf:compare -- <папка> [папка] [--verbose]` — сравнение двух выгрузок (узлы, меши, материалы, пиксели текстур, анимации по сэмплам, отчёт); вторая по умолчанию — `tools/.out/export`.
- `npm run scenes:compare` — рендер каждой сцены в three.js (Edge) рядом с эталоном Unity (`tools/unity-reference`): выгрузка → `tools/.out/compare/<id>.png` и опубликованная оптимизированная модель → `<id>-published.png` (пороги одни). Вручную: `https://localhost:5173/scene-preview.html?scene=<id>&t=<сек>` (только dev-сервер).
- `npm run assets:publish` — GLB (оптимизированные, `tools/assets/optimize.mjs`) и MP3 в `journey-ar/assets`, генерация `scenes.json`; привязка сцен к страницам — поиском текстур таргетов Vuforia на сканах (превью в `tools/.out/anchors/`). Уже записанные привязки сохраняются, пересчёт: `npm run assets:publish -- --reset-anchors`. Там же точка масштабирования (`pinch.pivot` — центр узлов из `pinchPivot` в `tools/scenes.mjs`).
- `npm run ui:publish` — ассеты интерфейса в `journey-ar/assets`: иконки из `original-sources/favicon/` (манифест — с именем и цветами приложения), `background.jpg` (картинка до включения камеры, из `original-sources/journey-art1600.jpg`) и `logo.svg` — фигурка путника, векторизованная из `mstile-150x150.png` (`tools/images/trace.mjs`: сглаживание, изолиния, упрощение) — для кнопки.
- `npm run pages:normalize` — сканы страниц → `pages-for-nft/<id>.jpg` (1700×1268, 142.5 dpi, симметричная обрезка).
- `npm run nft:generate -- [id...]` — NFT-маркеры (`.iset/.fset/.fset3`) в `journey-ar/assets/nft/<id>/` (`--pages=`, `--out=` для экспериментов); логи в `tools/.out/logs/`. Маркер — вся страница, а у сцены с `marker: 'target'` в `tools/scenes.mjs` (daqri) — место таргета Vuforia оригинала на странице (поиск по скану, как привязка), вырезанное из нормализованной страницы с тем же DPI (`tools/.out/nft-images/`). Прямоугольник маркера на странице (`region`, мм) пишется в `nft-report.json`, оттуда `assets:publish` переносит его в `scenes.json` → `marker`.
- `npm run nft:probe -- [id...] [--together] [--markers=<папка>]` — проверка маркеров без браузера: синтетические кадры с известной позой → Node-сборка jsartoolkit-nft → ошибка позы (в центре маркера), время детекта, путаница страниц; ракурсы маркера части страницы сдвинуты к нему и масштабированы по его ширине (`--together` — все маркеры в одном трекере, как в приложении). По умолчанию — маркеры приложения; относительная `--markers` считается от `tools/`.
- После смены страниц: `pages:normalize` → `nft:generate` → `assets:publish` → `nft:probe -- --together`.
- Конвейер сцен: `apk:convert` → `gltf:inspect` → `scenes:compare` → `assets:publish`. Unity не нужна.

## Правила

- Перед коммитом: `npm run check` и `npm run e2e` зелёные; `npm run e2e:full` — только в финале (перед отчётом о завершённой работе), он долгий.
- Ассеты в `journey-ar/assets` не правятся вручную — только скриптами из `tools/` (`assets:publish`, `ui:publish`); в `scenes.json` вручную/через debug-режим подстраиваются только `anchor`. Схема `scenes.json` — `journey-ar/src/scenes/manifest.ts`.
- Система страницы — мм, начало в центре страницы, X вправо, Y к верху страницы, Z из страницы. Трекер даёт позу маркера от его левого нижнего угла (`origin: 'corner'`); `markerToPage()` (`src/scenes/manifest.ts`) по `scenes.json` → `marker` (прямоугольник страницы, из которого сделан маркер) переводит её в позу страницы — точно, в отличие от `origin: 'center'` ядра, которое берёт размер по DPI, округлённому вниз. Поза страницы и точная поза vcam — матрица страница → камера в осях OpenGL, мм. Сцены в GLB — в системе таргета (ширина таргета = 1); перевод — `anchorMatrix()`.
- Сцен шесть, page166 (daqri) — последняя. Daqri отслеживается по кубу, как в оригинале (маркер — квадрат таргета Vuforia, ~99 мм), остальные — по всей странице. У daqri нет `PinchScale` (щипок задан в `tools/scenes.mjs` → `pinch`), звук — WAV из двух источников (`assets:publish` кодирует в MP3 и складывает громкости), прокрутка неба `SkyScroll` (legacy Animation) публикуется компонентом `AnimatedUVs_Scroll` (`uvScrolls` в `tools/scenes.mjs`); ссылка `TouchRay` на daqri.com и частицы не перенесены, надпись «Tap here» убрана (`removeNodes` в `tools/scenes.mjs`: `assets:publish` удаляет узел).
- Оптимизация GLB (`tools/assets/optimize.mjs`, при `assets:publish`) сохраняет структуру документа: узлы, их трансформации и текстуры не трогаются (приложение ищет узлы по именам, материалы берут текстуры по номеру из `extras`). Позиции не квантуются (иначе меши переезжают в новые дочерние узлы); нормали/касательные — 12 бит, UV в [0, 1] — 14, цвета вершин — 16 (линейные, в 8 битах тёмные полосят); всё сжато `EXT_meshopt_compression` без потерь; PNG → WebP (градиенты `*Ramp*` без потерь), JPEG как есть (их пишет конвертер, качество 90). gltf-transform пишет glTF-текстуры только для стандартных слотов — номера в `extras` после записи восстанавливаются по изображениям выгрузки (`restoreTextureRefs`); unit-тест в `manifest.test.ts`. Загрузчик — `GLTFLoader` с `MeshoptDecoder` (`src/scenes/load-scene.ts`). Изменения проверять `scenes:compare` (опубликованная модель должна давать ту же разницу с эталоном, что и выгрузка).
- Сцены берутся только из `original-sources/Journey-AR-Viewer.1.0.apk` (сборка 2012 года, Unity 3.5.5f3) конвертером под этот APK, без Unity:
  - `tools/apk/read-apk.py` (UnityPy, запуск `python -I`) читает APK напрямую: всё, что достижимо от корней `IT_*` и корневых огней, — typetree с разрешёнными ссылками (`objects.json`), декодированные меши (`data.bin`, полосы → треугольники), текстуры PNG (ARGB4444 — с перестановкой каналов RGBA ← A,R,G,B: сборка хранит их в порядке GLES), звук как есть. Поля скриптов (typetree MonoBehaviour в сборке 3.5 их не содержит) читаются из сырых байтов по раскладкам `SCRIPT_LAYOUTS` — только для скриптов на экспортируемых узлах; незнакомый скрипт — ошибка.
  - `tools/apk/convert.mjs` пишет GLB в формате прежней выгрузки UnityGLTF 2.24 + `extras` экспортёра Journey (на нём построены приложение и `assets:publish`): отражение по X, меш на узел с включённым рендерером (примитив на сабмеш, общие атрибуты), касательные с w = ±1, UV v перевёрнут, цвета вершин в линейном пространстве, свет `KHR_lights_punctual` (узел света повёрнут на 180° вокруг Y, его дети — под `<имя>-flipped`; интенсивность π·I², как в UnityGLTF), skin по bindposes, анимации — кривые legacy-клипов запекаются 30 к/с (`tools/apk/curves.mjs`: Hermite Unity, ключи, равные соседям, выбрасываются), JPEG для полностью непрозрачных текстур (качество 90), иначе PNG. Имена шейдеров — как в Unity 5+ (`Diffuse` → `Legacy Shaders/Diffuse` и т. п.), свойства и значения по умолчанию — из текста шейдера в APK, очередь рендера — из его тегов.
  - Сверка с прежней выгрузкой Unity — `gltf:compare` (эталон в `tools/.out/baseline/export`, вне git). Совпадают узлы, трансформации, меши, анимации, skin и `extras`. Отличия идут от пересборки, по которой был сделан Unity-проект, и решены в пользу APK: текстуры без размытия и DXT-артефактов импорта Unity (солнце Landscape — белое, как на телефоне), исходные имена без суффиксов рипа (`Sand_0` → `Sand`), у плаща Character `cape_cloth3` — материал с шейдером Detail (как у `cape_cloth2`), `spatialBlend` по клипу 3.5 (музыка 2D), клип по умолчанию отмечен, у Traveler_FBX клипа нет.
  - Читать APK для исследования — UnityPy из `tools/.out/pyenv` (`UnityPy.load(<apk>)` открывает APK как есть).
- AR-контент рендерится в gamma-режиме Unity: перед первым кадром `configureLegacyRendering(renderer, camera)`, текстуры сцен — `NoColorSpace`, цвета из Unity — как есть (`new Color(r, g, b)`), без `SRGBColorSpace`.
- Видео камеры рисуется внутри WebGL (`src/render/video-background.ts`, обрезка cover по центру, как проекция трекера) на непрозрачном контексте, который создаётся в `main.ts`; `<video>` только декодирует. Не возвращать прозрачный холст поверх видео: аддитивное смешивание тогда закрывает видео (свет Creature становится тёмным).
- Материалы сцен строятся только в `src/scenes/unity-materials.ts` по `extras.unityShader`. Любое изменение материалов, конвертера или рендера проверять `npm run scenes:compare` (пороги: средняя разница < 4/255, < 1 % пикселей > 32).
- Эталоны Unity (`tools/unity-reference`) отрендерены fixed-function шейдерами оригинала в Unity 6, без HDR намеренно (как 8-битный буфер телефона) — эталон оригинального вида; файлы не меняются.
- Отладка в `scene-preview.html`: `?t=` (время), `?hide=<материалы>`, `?ref=<папка эталонов в tools/.out>` (по умолчанию — `tools/unity-reference`).
- Трекинг: `src/tracking/` — jsartoolkit-nft в воркере (файлы воркера раздаются по `/nft-worker/` плагином в `vite.config.ts`), кадр 640 px по длинной стороне, одна активная страница, потеря на первом кадре без страницы, фильтр `native`. Портретное видео подаётся трекеру повёрнутым в альбомный кадр (`rotated` в геометрии), поэтому поворот телефона не пересоздаёт трекер. Показываемая поза сглаживается (`src/tracking/pose-smoother.ts`: One Euro + плавное догоняние на каждом кадре экрана). Диагностику ядра ARToolKit (версия, параметры камеры при каждом создании трекера, безвредная ошибка «Error detaching pattern» при остановке) глушит прелюдия, которую `vite.config.ts` ставит перед кодом воркера; остановка трекера ошибок не даёт (отклонённые запросы после `dispose` гасятся). Нагрузка: пока страницы нет в кадре, трекер ищет её раз в 200 мс (первую секунду после потери или старта — на каждом кадре; `src/tracking/search-pacer.ts`); кадр трекеру готовится на GPU из текстуры видео фона с асинхронным чтением (`src/render/gpu-frame-grabber.ts`; `?grab=canvas` — прежний путь через 2D-холст, `src/tracking/frame-grabber.ts`; он же выбирается сам при программном WebGL — SwiftShader в Chromium из Playwright, где асинхронное чтение медленное: в e2e путь через GPU проверяет Edge); холст рисуется только при новом кадре видео (частота камеры), не чаще 60 раз в секунду, до старта не рисуется. Параметры отладки: `?fov=<угол по длинной стороне>` (по умолчанию 63°), `?filter=native|none|oneeuro` (фильтр ядра трекера), `?smooth=off` или `?smooth=<minCutoff>,<beta>,<rotationBeta>,<easing>`, `?debug` (контур страницы и оси, у daqri — ещё контур маркера, оранжевый).
- Сцены: `src/scenes/ar-scenes.ts` — якорь (поза трекера) → `anchorMatrix(scene.anchor)` → GLB; ленивая загрузка, предзагрузка в фоне после старта трекера, перезапуск анимаций при каждом обнаружении (если страница вернулась в течение 3 с — продолжение с места остановки, `src/scenes/resume-window.ts`; так же и звук), скрытие в кадр потери. Жесты (`src/interaction/scene-gestures.ts`): щипок масштабирует узел `scenes.json` → `pinch.node` в пределах `pinch` относительно его начала или `pinch.pivot` (при уменьшении — точки страницы под ним, чтобы сцена стояла на странице; `src/scenes/pinch-pivot.ts`; Landscape — до 3× от центра моделей в сфере), перетаскивание (один палец, середина двух, мышь) сдвигает сцену в плоскости страницы (`page-point.ts`: точка страницы под пальцем следует за ним), двойное касание — сброс. Размер и сдвиг у каждой сцены сохраняются между обнаружениями (`scene-placement.ts`).
- Звук: `src/audio/scene-audio.ts` — Web Audio, AudioContext открывается кнопкой «Старт» (синхронно в клике); трек с начала при обнаружении (если страница вернулась в течение 3 с — с места остановки, `ResumeWindow`), затухание при потере, бесшовная петля (`loopBounds`), объёмный: `PannerNode` над центром сцены, позиция по сглаженной позе, модель затухания `SPATIAL` в `src/audio/loop-bounds.ts`. Состояние — `window.__journey.audio` (геттер с уровнями до/после панорамы).
- Интерфейс — только кнопка Старт/Стоп внизу по центру (`index.html`, `src/style.css`, `src/ui/start-button.ts`, решение пользователя — других элементов нет): чёрный круг с белым ободком и `logo.svg`; после «Старт» картинка инвертируется (белый круг, чёрная фигурка), ободок толще; пока грузятся NFT-маркеры, модели и звук, по тусклому ободку бежит огонёк (`src/ui/pending-loads.ts`, `window.__journey.loading`); после ошибки ободок красный до следующего «Старт». Запущенная и загруженная кнопка через 0.8 с сворачивается в полупрозрачную полоску (`collapsed`, имя «Показать кнопку»); нажатие или свайп вверх разворачивают её, без нажатия через 3 с она сворачивается снова (константы в `start-button.ts`; в тестах «Стоп» — через `pressStop` из `tests/e2e/helpers.ts`). Текста на экране нет: ошибки — только в консоли (`reportError` в `main.ts`). Пока камера не показывает картинку, холст скрыт и виден фон `background.jpg` (по центру, по высоте окна; класс `camera-on` у `body`). Имя кнопки для тестов — `aria-label` «Старт»/«Стоп».
- Выбор страницы: `src/tracking/page-selector.ts` — одна активная страница; при высокой ошибке трекинга (> 1.2) трекер временно ищет другие страницы, чтобы не держать неверную. Состояние — `window.__journey.scenes`. Состояние трекера — `window.__journey.tracking` (страница, поза, события found/lost); метрики по точной позе — `tests/e2e/tracking.spec.ts`.
- Тестовые источники кадров (`?source=canvas|webrtc|video`) работают только в dev/test-сборке (`import.meta.env.DEV`), запускаются кнопкой «Старт»:
  - `canvas` — виртуальная камера внутри приложения, управление через `window.__vcam`;
  - `webrtc` — поток из открытой vcam (`npm run dev:vcam`) через ретранслятор `/__signal` dev-сервера приложения (работает и на телефоне в LAN); `?room=<имя>` у обоих разводит несколько пар (тесты);
  - `video&src=/__recordings/<имя>.webm` — запись из `journey-ar/tests/recordings` (записи делает vcam: кнопка «Запись» или `__vcam.startRecording()`/`stopRecording(имя)`, рядом `<имя>.json` с точной позой каждого кадра).
- TypeScript закреплён на 6.0.x: typescript-eslint пока поддерживает только `<6.1`.
- three.js закреплён на точной версии (0.187.0) вместе с `@types/three`.
- `mind-ar` не устанавливать через npm: он тянет нативный `canvas` 2.x, который не собирается под Node 26. `.mind` компилировать в браузере (фаза 2).
- npm 11 блокирует install-скрипты; разрешённые перечислены в `allowScripts` корневого `package.json`.
